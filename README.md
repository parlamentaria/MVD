# 📚 Сайт с лекциями — инструкция по запуску

Готовый сайт для публикации лекций: главная страница, меню с лекциями слева, режим чтения, тёмная тема, мобильная версия и **админ-панель** со статистикой и редактором текста.

Хостинг — **GitHub Pages** (бесплатно), база данных — **Firebase** (бесплатный тариф Spark).

> ⏱ Настройка занимает примерно 20–30 минут. Ничего программировать не нужно — только скопировать пару значений.

## ✨ Что есть на сайте

**Для посетителей**
- Главная страница: заголовок, текст и одна кнопка-ссылка на другой сайт.
- Меню слева со всеми лекциями (на телефоне открывается кнопкой ☰), поиск по названиям.
- Лекции с форматированием: заголовки, **жирный**, *курсив*, подчёркивание, размеры текста, списки, цитаты, ссылки, картинки.
- **Режим чтения** — одна кнопка вверху справа (или клавиша `R`): убирает меню, делает фон «бумажным», текст крупнее; кнопки `A−` / `A+` меняют размер шрифта.
- Светлая и тёмная тема.
- Полоса прогресса чтения, время чтения, кнопки «Предыдущая / Следующая» (и стрелки ← → на клавиатуре).
- Внизу каждой страницы — карточка автора с контактами.
- Плавные анимации, адаптация под телефоны и планшеты.

**Для вас (админ-панель `admin.html`)**
- Вход только по вашему паролю.
- Статистика: всего просмотров, уникальные посетители, сегодня, за 7 дней, доля телефонов, график за 14 дней, **в какое время суток и в какие дни чаще читают**, самые популярные лекции.
- Добавление, редактирование, удаление лекций, изменение порядка, черновики (скрытые лекции).
- Редактирование текста главной страницы и информации об авторе.

## Шаг 1. Создайте проект Firebase

1. Откройте **https://console.firebase.google.com** и войдите через Google-аккаунт.
2. Нажмите **«Создать проект»** (Create a project / Get started).
3. Введите название, например `my-lectures`, нажмите «Продолжить».
4. Google Analytics можно **отключить** — он не нужен (статистика у сайта своя).
5. Нажмите **«Создать проект»** и дождитесь окончания.

Тариф по умолчанию — **Spark (бесплатный)**. Банковская карта не нужна.

---

## Шаг 2. Создайте базу данных Firestore

1. В меню слева: **Build (Создание) → Firestore Database**.
2. Нажмите **«Create database» (Создать базу данных)**.
3. Если спросит редакцию (edition) — выберите **Standard**.
4. Расположение (location): выберите ближайшее, например `eur3 (europe-west)`. ⚠️ Потом поменять нельзя.
5. Режим: **«Start in production mode»** (рабочий режим). Нажмите «Создать».

---

## Шаг 3. Подключите сайт к Firebase

1. Нажмите на **⚙️ шестерёнку** рядом с «Project Overview» → **Project settings (Настройки проекта)**.
2. Пролистайте вниз до блока **«Your apps» (Ваши приложения)** и нажмите иконку **`</>`** (Web).
3. Введите любое имя (например `site`). Галочку «Firebase Hosting» **не ставьте**. Нажмите **Register app**.
4. Появится код. Вам нужен только объект `firebaseConfig`, он выглядит так:

   ```js
   const firebaseConfig = {
     apiKey: "AIzaSyB...",
     authDomain: "my-lectures.firebaseapp.com",
     projectId: "my-lectures",
     storageBucket: "my-lectures.appspot.com",
     messagingSenderId: "123456789",
     appId: "1:123456789:web:abc123"
   };
   ```

5. Откройте файл **`js/config.js`** и замените значения в блоке `firebaseConfig` на свои (скопируйте 6 строк с кавычками и запятыми).

> 🔐 Это **не секретные** данные — их нормально хранить в открытом коде. Сайт защищают правила безопасности из Шага 5.

---

## Шаг 4. Создайте аккаунт администратора

1. В консоли Firebase: **Build → Authentication** → **«Get started» (Начать)**.
2. Вкладка **Sign-in method** → выберите **Email/Password** → включите первый переключатель **Enable** → **Save**.
3. Вкладка **Users** → **Add user (Добавить пользователя)**:
   - Email: ваша **настоящая** почта (на неё придёт письмо, если понадобится сбросить пароль);
   - Password: придумайте **надёжный** пароль (12+ символов).
4. В списке пользователей появится строка. Скопируйте значение из колонки **User UID** (длинная строка вроде `kT3x9QeB...`) — оно понадобится в следующем шаге.
5. В файле **`js/config.js`** впишите свой email:

   ```js
   export const ADMIN_EMAIL = "ваша@почта.ru";
   ```

   Тогда в админ-панели нужно будет вводить **только пароль**.

---

## Шаг 5. Вставьте правила безопасности

Правила определяют, кто что может делать с базой: посетители — только читать лекции и записывать просмотры, а менять лекции и смотреть статистику — **только вы**.

1. Откройте файл **`firestore.rules`** из проекта в любом текстовом редакторе.
2. Найдите строку:
   ```
   return request.auth != null && request.auth.uid == 'ВСТАВЬТЕ_СВОЙ_UID';
   ```
   и замените `ВСТАВЬТЕ_СВОЙ_UID` на UID из Шага 4 (кавычки оставьте!):
   ```
   return request.auth != null && request.auth.uid == 'kT3x9QeB...';
   ```
3. В консоли Firebase: **Firestore Database → вкладка Rules (Правила)**.
4. **Удалите всё**, что там написано, и вставьте весь текст из файла `firestore.rules`.
5. Нажмите **Publish (Опубликовать)**.

## Шаг 6. Укажите ссылку для кнопки на главной

В файле **`js/config.js`** найдите:

```js
homeButtonUrl: "https://example.com",
homeButtonNewTab: true,
```

- `homeButtonUrl` — адрес сайта, куда ведёт кнопка;
- `homeButtonNewTab` — `true` откроет ссылку в новой вкладке, `false` — в этой же.

Там же можно поменять название сайта (`name`) и подпись под ним (`tagline`).

Надпись на самой кнопке меняется в админ-панели (вкладка «Главная и автор»).

## Шаг 7. Загрузите сайт на GitHub Pages

1. Зарегистрируйтесь / войдите на **https://github.com**.
2. Справа вверху **«+» → New repository**.
   - Repository name: например `lectures`;
   - Тип: **Public** (для бесплатного GitHub Pages);
   - Нажмите **Create repository**.
3. На странице нового репозитория нажмите ссылку **«uploading an existing file»** (или **Add file → Upload files**).
4. Откройте папку проекта на компьютере, **выделите всё её содержимое** (файлы и папки `css`, `js`) и перетащите в окно браузера.
   > ⚠️ Перетаскивайте именно **содержимое** папки, а не саму папку — файл `index.html` должен оказаться в корне репозитория.
   >
   > ⚠️ Файл `.nojekyll` скрытый. На Windows включите «Показывать скрытые файлы» (Проводник → Вид), на Mac нажмите `Cmd + Shift + .`. Если не получилось загрузить его — не страшно, сайт будет работать и без него.
5. Внизу нажмите **Commit changes**.
6. Перейдите во вкладку **Settings → Pages** (в меню слева).
7. В разделе **Build and deployment**: Source — **Deploy from a branch**, Branch — **main**, папка **/ (root)** → **Save**.
8. Подождите 1–3 минуты и обновите страницу — появится адрес сайта:
   **`https://ВАШ-ЛОГИН.github.io/lectures/`**

> 💡 Если назвать репозиторий `ВАШ-ЛОГИН.github.io`, сайт будет доступен по короткому адресу `https://ВАШ-ЛОГИН.github.io/`.

---

## Шаг 8. Разрешите вход с вашего домена

Без этого шага вход в админ-панель на GitHub Pages выдаст ошибку.

1. Firebase → **Authentication → Settings (Настройки) → Authorized domains (Разрешённые домены)**.
2. Нажмите **Add domain** и впишите: `ВАШ-ЛОГИН.github.io` (без `https://` и без `/lectures`).
3. Сохраните.

---

## Шаг 9. Первый вход в админ-панель

1. Откройте **`https://ВАШ-ЛОГИН.github.io/lectures/admin.html`**
2. Введите пароль из Шага 4.
3. Перейдите во вкладку **«Лекции»** → нажмите **«Загрузить примеры»**, чтобы посмотреть, как выглядят лекции на сайте (потом их можно удалить), или сразу **«Новая лекция»**.
4. Во вкладке **«Главная и автор»** впишите свои тексты, имя и контакты → **Сохранить**.

🎉 Готово! Сайт работает.

> 💡 Ссылки на админ-панель на сайте нет — заходите по адресу `.../admin.html` напрямую (сохраните его в закладки). Даже если кто-то узнает адрес, без пароля он ничего не сможет сделать.

## 🛠 Как пользоваться админ-панелью

### Лекции
| Действие | Как сделать |
|---|---|
| Создать лекцию | «Новая лекция» → название → текст → «Сохранить» (или `Ctrl+S`) |
| Изменить | Нажмите на лекцию в списке или на ✏️ |
| Порядок в меню | Стрелки ▲ ▼ |
| Скрыть / показать | Кнопка 👁 — скрытая лекция становится черновиком и не видна посетителям |
| Удалить | 🗑 → подтвердить |
| Посмотреть на сайте | Кнопка ↗ |

### Панель форматирования
| Кнопка | Что делает |
|---|---|
| ↶ ↷ | Отменить / повторить |
| ¶ | Обычный текст |
| H1 H2 H3 | Заголовки разных уровней |
| **Ж** *К* <u>Ч</u> ~~З~~ | Жирный, курсив, подчёркнутый, зачёркнутый |
| A A A A | Размер текста: мелкий, обычный, крупный, очень крупный |
| списки, « » , — | Маркированный и нумерованный список, цитата, разделитель |
| 🔗 | Ссылка (выделите текст и нажмите) |
| 🖼 | Картинка по ссылке (`https://...`). Загрузить картинку можно, например, на imgbb.com или postimages.org и скопировать «прямую ссылку» |
| Tx | Убрать всё форматирование у выделенного текста |

**Как применить:** выделите текст мышкой → нажмите кнопку.
Текст можно вставлять из **Word** и **Google Docs** — жирный и курсив сохранятся, лишнее оформление удалится автоматически.

### Статистика
- Каждый посетитель засчитывается **один раз на страницу за сессию** (обновление страницы не накручивает счётчик).
- Время в графиках — **местное время посетителя**.
- Галочка «Не учитывать мои просмотры с этого устройства» включена автоматически после входа — ваши собственные визиты не портят статистику.

## 🔄 Как обновлять сайт после изменений в коде

Лекции и тексты меняются **через админ-панель** — код трогать не нужно, изменения видны сразу.

Если вы поменяли файл (например, `js/config.js` или цвета в `css/style.css`):
1. Откройте репозиторий на GitHub → нужную папку → **Add file → Upload files**.
2. Перетащите изменённый файл (он заменит старый) → **Commit changes**.
3. Через 1–3 минуты изменения появятся на сайте. Если не видно — обновите страницу с очисткой кэша: `Ctrl + F5` (Mac: `Cmd + Shift + R`).

Также файл можно отредактировать прямо на GitHub: откройте его → значок ✏️ → правки → **Commit changes**.

## 🎨 Как поменять цвета и шрифты

**Цвета** — в начале файла `css/style.css`, блок `:root`:
```css
--accent: #6a5af9;      /* основной цвет */
--accent-2: #a259ff;
--accent-3: #14b8d4;
--grad: linear-gradient(135deg, #6a5af9 0%, #a259ff 50%, #14b8d4 100%);
```
Подобрать цвет можно на https://htmlcolorcodes.com/ru/. Цвета тёмной темы — в блоке `[data-theme="dark"]` ниже, режима чтения — в `html.reading`.

**Шрифты** — сейчас используются **Manrope** (интерфейс и заголовки) и **Literata** (текст лекций, специально создан для чтения с экрана). Оба поддерживают кириллицу.
Чтобы заменить: выберите шрифт на https://fonts.google.com (с поддержкой Cyrillic), поменяйте ссылку `fonts.googleapis.com` в `index.html` и `admin.html`, и названия в `--font-ui` / `--font-read` в `style.css`.

## 🔐 Безопасность

- Ключи в `js/config.js` — публичные, так задумано Firebase. Защиту обеспечивают **правила Firestore** (Шаг 5): изменять данные и читать статистику может только аккаунт с вашим UID.
- Весь текст лекций проходит очистку — вредный код (скрипты и т. п.) не попадёт на сайт, даже если вставить его в редактор.
- Используйте **надёжный пароль**. Сменить его: Firebase → Authentication → Users → «⋮» напротив пользователя → **Reset password** — на почту придёт ссылка для смены пароля. (Или удалите пользователя и создайте нового — тогда обновите UID в правилах.)
- Дополнительно (по желанию): Authentication → Settings → **User actions** → снимите галочку **Enable create (sign-up)**, чтобы никто не мог зарегистрироваться через API. На безопасность данных это не влияет (права есть только у вашего UID), но так чище.

## 📊 Ограничения бесплатного тарифа

Тариф Firebase **Spark** бесплатный и не требует карты. Лимиты в сутки:

| Что | Лимит в день | Чем расходуется |
|---|---|---|
| Записи | 20 000 | 1 просмотр страницы = 1–2 записи |
| Чтения | 50 000 | открытие сайта ≈ 2–20 чтений; открытие статистики ≈ 60 чтений |

Этого хватает примерно на **10 000 просмотров в день**. Если лимит закончится, сайт продолжит работать на следующий день; оплату Firebase сам не спишет.

## ❓ Частые проблемы и решения

**Открываю `index.html` двойным кликом — пустая страница / красная плашка.**
Современный JavaScript не работает при открытии файла напрямую. Варианты:
- загрузите на GitHub Pages (Шаг 7) и смотрите там;
- или установите [VS Code](https://code.visualstudio.com/) + расширение **Live Server** → правый клик по `index.html` → «Open with Live Server»;
- или в папке проекта выполните `python -m http.server 8000` и откройте http://localhost:8000.

**Внизу меню написано «Демо-режим».**
Не заполнены настройки Firebase в `js/config.js` (Шаг 3), или новый файл ещё не загружен на GitHub.

**В админке: «Неверный пароль».**
Проверьте пароль и email в `ADMIN_EMAIL` (Шаг 4). Пароль можно сбросить в Firebase → Authentication → Users.

**В админке: «Этот домен не разрешён…» (`auth/unauthorized-domain`).**
Выполните Шаг 8.

**В админке: «Нет прав» / «Нет доступа к данным».**
UID в правилах не совпадает с UID пользователя или правила не опубликованы. Повторите Шаг 5 внимательно (UID в одинарных кавычках, кнопка Publish).

**На сайте: «Не удалось загрузить лекции».**
Проверьте, что правила из Шага 5 опубликованы и в `config.js` правильный `projectId`.

**Лекция есть в админке, но не видна на сайте.**
Она скрыта (черновик) — включите переключатель «Опубликована» или кнопку 👁 в списке.

**Изменения в коде не видны на сайте.**
Подождите 1–3 минуты после загрузки на GitHub и обновите страницу с `Ctrl + F5`. Статус публикации видно во вкладке **Actions** репозитория.

**Статистика пустая.**
Просмотры появятся, когда сайт откроют посетители. Ваши собственные визиты с устройства, где вы входили в админку, не считаются (можно отключить галочкой внизу вкладки «Статистика»).
